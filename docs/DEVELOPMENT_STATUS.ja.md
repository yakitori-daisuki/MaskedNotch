## ビルド・起動

Xcode 26.5とmacOS SDK 26.5で確認しています。ネットワークへのパッケージ解決は不要です。

```sh
./script/build_and_run.sh --build   # Debugをビルドするだけ
./script/build_and_run.sh --probe   # 初回案内なし、90秒後に自動終了する試験起動
./script/build_and_run.sh           # 通常起動。自動終了なし
MASKED_NOTCH_CONFIGURATION=Release ./script/build_and_run.sh --probe # Releaseの試験
```

通常起動では初回のみ標準アラートで設定と検証上の制約を案内します。ロック中や別ユーザーのコンソールでは表示を延期します。試験起動は初回案内の確認済み状態を保存しません。

生成物は `build/DerivedData/Build/Products/Debug/MaskedNotch.app` です。Xcodeで `MaskedNotch.xcodeproj` を開き、`MaskedNotch` スキーム／My Macを選んでRunすることもできます。プロジェクトは生成済みで、PythonやXcodeGenは通常のビルドに不要です。

Release生成物は同じProducts内の `Release/MaskedNotch.app` です。作業時に作成した `build/MaskedNotch-local.zip` にもローカル署名版を収めています。配布署名・公証済みのパッケージではありません。

日常利用やログイン時起動の試験では、アプリを終了し、自分で `~/Applications` または `/Applications` など固定した場所へ `.app` をコピーしてから起動してください。自動インストールは行いません。ビルドスクリプトはこのアプリ名の既存プロセスだけを終了してから起動します。他アプリには操作しません。

`--verify` はプロセス存在確認、`--debug` はLLDB、`--logs`／`--telemetry` はこのアプリのOSログ表示です。**プロセス存在＝帯の表示成功ではありません。** ログはローカルのUnified Loggingのみです。

`./script/build_and_run.sh --inspect` は現在の設定と帯の配置をJSONで読み取ります。
このモードはビルド・終了・起動・設定変更を行わないため、再発中の状態を保ったまま実行できます。
メニューバー背景は開発用の読み取り専用SPI、透明度は公開API、自作アプリの設定はPreferencesから取得します。
SPIが使えない場合は不明として出力します。画面画像を取得する機能ではなく、最終画面の色は判定しません。

開発用の `python3 script/capture_desktop2_strip.py --wait` は、表示中のSpaceがデスクトップ2になるまで最大45秒待ち、内蔵画面の上端38ポイントだけを1回撮影します。このMacでは3600×76ピクセルです。前後のSpace番号と寸法を検査し、デスクトップ2でない場合は撮影せず、取得中の切り替わりを検出した場合は画像を破棄します。画像と診断情報は `build/desktop2-review/` に保存します。Spaceの切り替えや権限・設定の変更はしません。これは作業範囲を絞る確認処理であり、macOSのデスクトップ単位のアクセス権限ではありません。通常アプリには含めません。

開発用の `--probe-refresh` は、0.5秒ごとの「再描画」と「表示順の再設定」を定期更新なしの動作と比較し、約110秒で自動終了する試験です。試験中は通常版の定期更新を無効化し、各区間だけを比較します。[試験手順・実測値・限界](REFRESH_EXPERIMENT.md)を参照してください。

## メニュー

Build 9から日本語・英語に対応しています。起動時にmacOSの優先言語（アプリ個別の指定があればその指定）に従い、対応する言語がない場合は英語を表示します。言語を変更したあとはアプリを再起動してください。メニュー、アプリ情報、案内・エラー文、読み上げ用ラベルを翻訳しています。

翻訳リソースは `Resources/en.lproj/Localizable.strings` と `Resources/ja.lproj/Localizable.strings` です。`python3 script/test_localizations.py` でパッケージ内の30項目、書式引数、ソースのキーの網羅性と5種類の優先言語設定を検証できます。検証用のFoundationプログラムだけを実行し、本体の起動や保存された言語設定の変更は行いません。Build 9ではReleaseビルド・署名検証と、この5条件の検証が成功しました。画面レイアウトの目視確認とは区別します。

1. **ノッチを隠す**：初期値オン。保存され、通常画面とロック画面で共用します。
2. **ログイン時に起動**：初期状態では登録しません。クリックで `SMAppService.mainApp` を登録／解除します。チェックは実際の `.enabled` のときだけです。「承認待ち」は横線表示で、再度クリックすると解除します。「検出不可」はOSの `.notFound` で、クリック時に登録を試み、失敗理由を案内します。
3. **このアプリについて**：Build 8で追加。バージョン・ビルド番号・表示方式・実行中のアプリの場所を標準の情報パネルに表示します。
4. **終了**：自作パネルを閉じ、通知を解除して終了します。ログイン時起動の登録は別操作です。

メニューバーのアイコンは、「ノッチを隠す」がオンなら画面の上端全幅に帯、オフなら中央だけにノッチを描きます。設定の切り替え直後と、保存状態を読み込む起動時に反映します。マウスを重ねた説明と読み上げラベルにもオン／オフが表示されます。アイコンは設定状態を表し、OSとの合成結果を自動判定するものではありません。

承認が必要な場合は、自分でシステム設定 → 一般 → ログイン項目と機能拡張を確認してください。OS側で変更した状態はメニューを開くたびに読み直します。Dockアイコン、通常のメインウィンドウ、設定画面、ショートカットはありません。

## 必要なOS設定と視認性

通常デスクトップの最初の試験は、以下の条件で始めてください。

- システム設定 → メニューバー → **メニューバーの背景を表示：オフ**。
- システム設定 → アクセシビリティ → ディスプレイ → **透明度を下げる：オフ**。

これらを自動変更しません。「メニューバーの背景を表示」はアプリから取得・判定していません。開発時の別途読み取りでは背景のぼかし設定とReduce Transparencyがfalseでも青い表示が残りました。したがって、この設定手順だけで直るとは案内できません。不透明なOS背景が有効だと、その下の黒帯が見えない可能性もあります。

黒帯は通常 `NSWindow.Level.statusBar - 1` にあります。OSのメニュー文字やアイコンを白くするAPIは呼びません。パネルの外観を変えればOSの文字色まで変わる、とも仮定していません。**明るい／暗い壁紙 × ライト／ダーク外観で、Appleメニュー・アプリメニュー・時計・アイコンを別々に読んで操作してください。** 黒い文字が黒帯に埋もれる条件は未解決です。問題があれば「ノッチを隠す」をオフにしてください。黒帯が出るだけでは合格ではありません。

## ロック画面

ログイン済みの自分のセッションで、ロック通知を受けたときだけ専用のSkyLight Spaceに黒帯を配置します。解除時はそのパネルを閉じ、通常表示用パネルへ戻します。再起動直後のログイン前、ログアウト後、FileVault解除画面、別ユーザーのセッションは対象外です。

SkyLightWindowの固定版を小さく改変して同梱しています。ロック用Spaceのレベルは元実装の400ですが、ウィンドウレベルを最大値にはしません。**Space 400でもOSの上端表示を覆う可能性があり、実機検証で排除できていません。** 認証UIやセキュリティ表示を覆う場合は不合格です。READMEのチェック表に結果を残して調整する必要があります。

最初は `./script/build_and_run.sh --probe` で起動し、90秒以内に標準空撮のロック画面と解除を確認してください。自動終了の3秒後までにメイン処理が止まっていても、試験プロセス自体を終了する保険があります。アプリはロック操作や認証入力を自動実行しません。

開発用の `./script/build_and_run.sh --probe-backend` は15秒の試験です。表示しないパネルでSkyLightの呼び出しと撤去を確認してから通常帯を生成します。**これはロック画面の実機試験の代替にはなりません。** 診断ログを確認するには、ターミナルで以下を実行します。

```sh
log show --last 5m --style compact --predicate 'subsystem == "local.MaskedNotch"'
```

プライベートAPIの読込・シンボル・戻り値が失敗したらロック用パネルを閉じ、その起動中のロック表示を停止します。通常デスクトップは可能な限り継続し、解除後に案内します。OS更新後もこの方法が使える保証はありません。SIP無効化、管理者権限、認証回避、他プロセスへの注入は行いません。

## ディスプレイ・Spaces・復帰

- `NSScreen.main` に依存せず、内蔵かつactive/onlineな画面から選びます。safe areaと左右auxiliary areaでノッチを確認します。
- 高さはsafe areaの上端除外量です。メニューバー全体の高さや固定値ではありません。位置はポイントで計算し、下端だけ1物理ピクセル未満の範囲で外側に丸めます。
- 対象画面なし、クラムシェル、ミラーリングでは表示しません。ミラーリングは外部への複製を避けるため対象外です。
- 画面構成、Spaces、アプリ切替、システムpresentation options、ロック／解除、セッション、スリープ／復帰通知で更新します。イベント後だけ0.15／0.5／1.5秒の最大3回再試行を行います。
- オフ・終了や新しい通知で古い再試行を無効化します。通常版とロック中は最大1枚、Build 7 Desktopの通常画面は3枚（入れ替え中のみ4枚）です。ロック用Spaceは最大1個を再利用し、未使用時は空で非表示のまま保ちます。プロセス終了で接続とともに解放されます。
- 通常パネルは `.stationary` を指定し、画面切替後は公開ウィンドウ情報から対象のOSメニューバーを探して、その下へ並べ直します。フルスクリーン補助ウィンドウにはせず、fullscreen／menu非表示のsystem presentation状態でも撤去します。**この修正後も通常画面は青いままと利用者から報告されました。** Mission Controlの視認性・操作への効果は未検証です。

## OnlySwitchからの手動移行

1. OnlySwitchの「ノッチを隠す」をオフにする。
2. OnlySwitchを終了する。
3. 必要ならmacOSの壁紙設定で、標準空撮・シャッフルを手動で再選択する。
4. Masked Notchを試験起動し、メニューの視認性とロック画面を確認する。
5. 合格後に通常起動し、必要なら「ログイン時に起動」を自分でオンにする。

OnlySwitchや他のメニューバーアプリを自動停止・削除したり、設定や壁紙を移行・復元したりする機能はありません。

## 停止・削除

一時的に帯を撤去するには「ノッチを隠す」をオフにします。完全に停止するには「終了」です。

削除時は、まず「ログイン時に起動」をオフにしてOSの登録解除を確認し、終了後に `.app` をゴミ箱へ移してください。必要ならシステム設定側のログイン項目も確認します。自作設定だけを消したい場合は終了後に `defaults delete local.MaskedNotch` を手動で実行できます。壁紙の復旧操作は不要です。

試験中の緊急停止は自動終了を待つか、ターミナルから `pkill -x MaskedNotch`、またはアクティビティモニタでこのアプリのみを終了してください。WindowServerやDockを再起動する必要はありません。

## 署名・配布

ローカルビルドはad-hoc署名（`CODE_SIGN_IDENTITY=-`）です。DebugにはXcodeのデバッグ用 `get-task-allow` が付きます。画面収録・アクセシビリティ・入力監視・フルディスクアクセス等の権限要求コード、ネットワーク通信、分析SDK、更新機構、daemonやhelper processはありません。

ログイン時起動はOSの署名・bundle配置・承認状態にも依存します。開発用ビルドで成功したと仮定しないでください。配布する場合は別途Developer ID署名、Hardened Runtime、Release成果物の検証、公証、stapleが必要です。配布用の署名・公証はこの作業では実施していません。App Store可否も保証しません。

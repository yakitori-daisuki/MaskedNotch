# Build 7：3方式を重ねるDesktop版

2026-09-09、利用者の「いろいろな方法を重ねて常に黒帯を出す」という依頼で追加。
`/Applications/Masked Notch Desktop.app` を更新して時間制限なしで起動した。
利用者から **「黒くなり、文字やアイコンも見える」** と確認を得た。
この時点の表示成功として記録する。長時間やスリープ・ロック等の全条件の保証ではない。

その後、同日に **「効かなくなってる」** と再発が報告された。現在は未解決。
02:09:41 JSTの読み取りでは同じPID 30842、Build 7、hideNotch=trueのまま、
3方式の帯が上端1800×38ポイントに残っていた（入れ替え中のため画面上4枚）。
メニューバー背景とReduce Transparencyもfalseだった。
この情報は最終画面の色を表さないため、帯の消失や設定オフを原因とは断定できない。
再発中の取得結果は `docs/evidence/layered-build7-recurrence-state.json` に保存した。

利用者がデスクトップ2だけの画面確認を希望したため、表示中のSpaceを前後に確認し、
上端の帯の範囲だけを取得する開発用スクリプトを追加した。
`python3 script/capture_desktop2_strip.py --wait` は最大45秒待機する。
最初の待機ではデスクトップ1のままだったため、画像を取得していない。
画面の範囲指定は運用上の確認であり、OSのSpace単位の権限ではない。

## 構成

| 位置 | 描画方法 | このMacのレベル |
|---|---|---:|
| 壁紙直上 | 不透明NSPanelの黒い背景色 | −2147483622 |
| 通常アプリの下 | CALayerへ不透明な黒い画像を提出 | −1 |
| OSメニューバー直下 | NSViewのdrawでQuartz塗りつぶし | 24 |

デスクトップでは同じ38ポイントの領域へ3枚を重ねる。
0.5秒ごとに描画と配置を更新し、1秒ごとにメニュー直下の帯を作り直す。
新しい帯を表示してから0.1秒後に古い帯を閉じるため、アプリが全枚数を同時に
隠す点滅処理は使わない。入れ替え中の所有パネルは最大4枚。
新しい帯の表示要求が失敗した場合は、古い帯を維持する。

オフ、終了、スリープ、対象画面消失、ロックへの移行でデスクトップの全パネルを撤去する。
入れ替え予約も取り消す。各定期更新前にセッションと画面を再確認する。
ロック中は従来のSkyLight用パネル1枚に切り替わり、デスクトップの多重表示と混在させない。
従来同様、公開presentation情報だけでは全画面の全条件を判定できるとは保証しない。

壁紙・OS設定・Thaw設定・ログイン時起動設定は変更しない。
通常版・A/B・点滅版には自動で有効化せず、Desktop版のInfo.plistに
`MaskedNotchLayeredBands=true` を設定する。メニューバーには「重ね」と表示する。

## 検証

- Core 20件、Xcode 36件に成功。Quartzの黒い画素、入れ替えの上限、
  重なり中の撤去、表示要求失敗時の継続を検証した。
- Releaseビルドとstrict署名検証成功。
- 01:12:44〜01:13:04 JSTの20秒試験で3方式を作成し、19回の入れ替えを記録。
  Quartz描画45回、CALayerへの画像提出44回。アプリ内描画の記録を最終画面の色と混同しない。
- 自動終了で全パネルを撤去し、その後の公開ウィンドウ一覧に本アプリの帯が残らないことを確認。
- 01:14:58 JSTにインストール先から通常起動。PID 30842、Build 7、hideNotch=true。
- 15.13秒の10回の測定で、画面上の帯は3枚、入れ替え中のみ4枚。
  全てalpha=1、位置(0,0)、1800×38ポイント。低い2枚のIDは固定、メニュー直下だけ更新。
- 公開ウィンドウ順序はOSメニュー→Thaw→本アプリのレベル24の帯。
  本アプリの他の2枚もOSメニューより下だった。
- 同期間の本アプリのCPU時間は0.21秒、RSSは46,640→46,672 KiB。
  約1.4%の1コア相当。短時間の値であり、長期の負荷・消費電力の測定ではない。

全ウィンドウ取得（`optionAll`）には非表示の帯の記録も1件含まれたため、
最初の「全記録が最大4件」という診断側のassertionは失敗した。
画面上の枚数は`kCGWindowIsOnscreen=true`で区別し、3〜4枚であることを確認した。
非表示記録の件数はこの測定で増加していない。原因・長期の資源解放までは断定しない。
最初の取得結果と、集計方法の訂正の両方を保存している。

## 残る確認

### Build 10：Space切り替え時の全描画面更新

2026-09-09、複数デスクトップへの対応依頼を受けた。変更前のBuild 9を
`script/inspect_spaces.swift --bands`で調べると、レベル24／−1／壁紙直上の
3枚ともSpace ID 1と1565の両方に所属していた。`canJoinAllSpaces`の不足とは判断できない。
この所属読み取りは開発診断だけで、製品には非公開のSpace所属APIを追加していない。
診断ABIの参照：[CGSInternal](https://github.com/NUIKit/CGSInternal/blob/master/CGSSpace.h)。

従来は切り替え時に再配置・再描画するだけで下側2枚が残っていたため、
Build 10は`activeSpaceDidChangeNotification`で3方式の更新を予約する。
既存の表示可能状態の判定後、1枚ずつ新しいパネルを表示して旧パネルを閉じる。
最大4枚を守り、失敗した更新は保留して再試行する。通常のアプリ切り替えでは全更新を予約しない。
監視対象の下側パネルが入れ替わった場合は、active Spaceの監視も新しいパネルに付け替える。
Core 20件・Xcode 38件のテストに成功。これは描画面更新の対策であり、
両デスクトップの見た目が正常と確認できるまでは実機合格としない。

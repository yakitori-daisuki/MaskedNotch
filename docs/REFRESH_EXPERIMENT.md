# 0.5秒更新の比較試験 — 2026-09-08

通常画面で青／グレーに戻るとの再報告を受け、定期的な再描画と表示順の再設定を別々に比較する開発用試験を追加しました。通常起動では有効になりません。

```sh
MASKED_NOTCH_CONFIGURATION=Release ./script/build_and_run.sh --probe-refresh
```

起動後5秒は準備、続いて通常動作20秒、再描画40秒、表示順の再設定40秒。約110秒でアプリは自動終了します。各区間はOSのスケジューリングで遅れる場合があり、実際の経過時間と実行回数をログへ記録します。

- 通常動作：既存の通知と有界再試行のみ。
- A／再描画：既存パネルの描画面を0.5秒間隔で更新。表示順の追加変更はしません。
- B／表示順：0.5秒間隔で既存パネルをOSメニューバーの下へ並べ直します。明示的な再描画は追加しません。
- 通常の通知による処理は全区間で共通です。OSの内部描画まで分離できる試験ではありません。
- タイマーはパネルを作り直しません。オフ、対象画面なし、ロック、別セッション、sleep、終了、fullscreen/menu非表示では追加更新をしません。停止と区間切替には世代照合があります。
- OSの設定、文字色、壁紙、パネルのレベルは変更しません。レベル24のままです。
- 計測するCPU時間はgetrusageによるアプリ自身のuser＋system時間の差です。CPU比率は1コアを100%として、各区間の実時間で割ります。バッテリー・GPU・WindowServerの増分負荷を示す値ではありません。
- ログはlocal.MaskedNotch／Probeのrefresh-probe行です。画面内容、認証入力、設定の読み取りはありません。

自動テスト：既存23件に、完了後の停止・多重start防止、途中停止後のtick／次区間抑止、不正／100秒を超える実験時間の拒否を追加。Xcode 26件・SwiftPM 20件が成功しました。SwiftPMの20件はXcodeにも含まれます。

視認性・ちらつき・OS文字と操作については、各区間の利用者報告が必要です。CPU時間や描画API成功から表示成功を推定しません。
